# 按课节作业后视频播放设计

## 背景

当前自动学习流程将一个课节内的视频与作业分别处理：视频通常先播放，之后再处理作业；视频完成还依赖固定的 95% 配置。实际课程存在以下约束：

- 一个章节包含多个课节；每个课节包含作业题和视频任务。
- 每个课节必须先成功处理作业，再播放该课节的视频。
- 作业失败时不能启动该课节的视频，应只重答当前课节。
- 视频任务点的完成条件可能是 90%、100% 或其他平台规则，不能固定使用 95%。
- 页面任务点图标才是完成判据；图标显示未完成时不能只依据播放时间跳过。
- 一个视频内可能多次弹出非作业题，每次都必须单独处理。
- 多课节仍可并发，但并发不意味着把整个课程拆成统一作业阶段和统一视频阶段。

## 目标

1. 普通 `study` 和 `study:dry` 对每个课节执行：作业 → 该课节视频（视频任务按页面顺序逐个播放）。
2. `--concurrency 1` 时按目录顺序逐节处理；`--concurrency 2/3` 时可同时处理多个已解锁课节，每个课节内部顺序不变。
3. 正式模式下，作业必须成功提交后才进入视频；作业重答达到上限、验证码或不可恢复错误时跳过该节视频。
4. `--dry-run` 下作业只填答不提交；填答成功即可进入视频，并在状态与终端中明确显示未提交演练状态。
5. 保留 `--phase video` 为明确的仅视频例外，不处理作业；保留 `--phase homework` 为仅作业模式。
6. 视频默认自然播放到 100%；如果当前视频任务点图标提前明确为已完成，可以提前进入下一个视频。
7. 视频没有可识别任务点完成图标时，只能自然播放到 100% 后视为播放完成。
8. 视频自然播放到结尾但任务点仍未完成时，等待平台同步；超时仍未完成则标记失败，不启动该课节后续视频。
9. 视频播放期间每次发现新的弹题都处理；不使用整个视频累计三次的限制。单次弹题内部仍保留有限选项尝试，无法通过则当前视频失败。
10. 不 seek、不拖拽、不伪造焦点、不绕过验证码或闯关锁定。

## 非目标

- 不改变 `--phase video` 的明确仅视频语义。
- 不把不同课节的作业和视频重排成全局两个阶段。
- 不通过修改 `currentTime` 或跳转进度伪造完成。
- 不在没有任务点完成图标时猜测平台完成状态。
- 不增加并发上限；继续使用 1–3。

## 课节调度

调度器继续按课程目录顺序选择未完成、未锁定课节。每个工作页面一次只领取一个课节，执行完整的课节流水线：

```text
领取课节
  ↓
刷新并发现该课节任务
  ↓
普通模式：处理该课节作业并重答
  ↓ 作业成功提交
  ↓
依次播放该课节的视频任务
  ↓
课节完成 / 失败
```

`--phase video` 跳过作业前置，直接依次播放视频；`--phase homework` 在视频前停止，仅处理作业。

多个课节并发时，每个页面有独立的阶段状态和进度条。例如页面 1 可以处于作业重答，页面 2 可以处于视频播放，但页面 1 只有作业成功后才能进入视频。

课节作业失败不会释放为“可播放视频”的状态。该工作页面记录失败并结束当前课节，调度器可以继续其他并发课节；同一课节不在本轮自动跳过失败直接播放视频。

## 作业前置规则

### 正式模式

- 如果课节作业已经提交，直接进入视频阶段。
- 如果仍需作业，沿用现有答案生成、提交确认、平台状态对账和最多三次重答机制。
- 只有 `submitted` 才能进入视频。
- `failed`、`blocked`、`uncertain` 或验证码状态都结束该课节，不播放其视频。

### 演练模式

- 作业按现有逻辑读取题目、生成并填写答案，但不点击正式提交。
- 全部题目成功填写且结果为 `dry-run` 时，视为“作业前置通过”，允许进入视频。
- 终端进度显示“作业未提交（演练）”，备忘录继续保存 `dry_run` 和答案。
- 无法完整填答、题目不支持或读取失败时，仍视为作业失败，不播放视频。

## 视频任务点完成判定

### 当前任务点定位

播放单个视频前，工作页面记录当前视频任务的稳定身份（优先 `cardId`，其次 `tabId`，最后任务顺序），并在任务点标签或其关联 DOM 中读取：

- 完成图标的 `aria-label`、文本、class 或明确完成标识；
- 完成条件文本，例如 `观看时长需 ≥ 总时长的 90%`；
- 是否存在可识别的任务点完成状态。

不能只用课节总进度或其他视频的图标作为当前视频完成判据。

### 播放目标

- 默认目标是自然播放到视频结束，即 100%。
- 不根据“完成条件 ≥90%”把播放目标提前改为 90%；该文字用于解释平台条件和辅助状态显示，不能取代任务点图标。
- 若当前视频任务点图标在自然播放结束前明确显示已完成，可立即停止等待并进入下一个视频。
- 如果有图标但图标仍为未完成，视频自然播放到 100% 后进入同步等待；同步等待超过配置的完成确认超时仍未完成，当前视频失败。
- 如果没有可识别图标，视频自然播放到 100% 后视为播放完成，沿用平台最终状态记录，不伪造图标完成。
- 默认继续使用配置的 2×播放尝试。程序不主动因页面提示而修改倍速；平台若强制 1×，以实际播放器状态为准。

### 任务点状态解析

解析器应区分三类结果：

```text
completed       明确显示任务点已完成
pending         明确显示任务点未完成
unavailable     当前页面没有可识别的任务点状态
```

解析优先级为明确的完成/未完成语义，其次是稳定的 class/属性规则；未知内容不得被当成 `completed`。解析器须支持示例：

```html
<div class="ans-job-icon ans-job-video ans-job-icon-clear"
     aria-label="任务点未完成" role="option">
  <div class="task-condition">
    <span class="special-text">完成条件</span>
    观看时长需 ≥ 总时长的 90%
  </div>
</div>
```

完成状态的实际 class 或 aria-label 以平台运行时 DOM 为准，选择器应集中在 `src/study-selectors.mjs` 或独立的任务点状态模块中。

### 课节内顺序

视频任务按 `discoverLessonTasks` 返回顺序处理。当前视频未达到“明确完成”或“自然播放 100% 且无图标状态”条件前，不点击下一个视频。任一视频失败，当前课节剩余视频不再播放并记录失败。

## 视频内弹题

`waitForMediaTarget` 的每次轮询都检查当前视频弹题是否可见：

1. 弹题从不可见变为可见时，生成一次处理事件。
2. 处理该弹题并等待其关闭或继续按钮完成。
3. 弹题关闭后重置停滞计时，继续读取视频和任务点状态。
4. 后续播放时间再次出现新弹题时重复上述流程。

不使用跨整个视频的累计 `maxAttempts`。同一弹题持续显示时，不重复创建新的处理事件；单次弹题内部仍逐选项尝试，超过单题选项范围或无法关闭则当前视频失败。

应记录每次弹题的序号、处理状态和错误，但不把视频内弹题与章节作业状态混淆。

## 终端进度与持久化

每个工作页面进度包含：

- 作业阶段：读取、生成答案、重答第 N/3 次、提交、作业未提交（演练）；
- 视频阶段：当前视频标题、实际播放时间、总时长、播放百分比、任务点状态；
- 视频弹题阶段：正在处理第 N 次弹题或处理失败；
- 课节最终状态：完成、作业失败、视频失败、锁定。

视频进度百分比只表示媒体实际播放时间，不把它强行显示为任务点完成；任务点完成单独显示。已有 `StudyMemoStore.mutate` 串行写入机制继续使用。作业失败时不得写入视频 `done`；视频失败时不得写入课节整体 `done`。

## 错误处理

- 作业最终失败：记录作业错误，跳过本节视频，释放页面给其他课节。
- 单个视频弹题无法通过：记录当前视频失败，停止本节剩余视频。
- 视频播完但任务点未完成：等待同步超时后失败，不进入下一个视频。
- 页面关闭或浏览器上下文故障：按现有全局失败处理，停止调度并生成失败报告。
- 任务点状态解析未知：使用 100% 播放策略，不把未知状态当作已完成；若存在图标但无法判断其状态，应记录解析警告并采用“播放结束后等待确认”的保守策略。
- 课节锁定：不领取、不打开，等待目录刷新后再判断。

## 测试设计

### 单元测试

1. 解析 `aria-label="任务点未完成"` 为 `pending`。
2. 解析明确完成文本/class 为 `completed`。
3. 未识别 DOM 返回 `unavailable`，不会返回 `completed`。
4. 完成条件文字包含 90% 时，播放目标仍为 100%。
5. 没有任务点状态时自然播放到 100%。
6. 播放到结尾但任务点 pending 时进入同步等待并最终失败。
7. 任务点提前 completed 时可提前结束当前视频。
8. 同一视频多次弹题逐次处理；同一弹题持续显示不重复处理。
9. 单次弹题选项尝试失败会停止当前视频。

### 流程测试

1. 整章串行：第 1 节作业成功 → 第 1 节视频依次播放 → 第 2 节作业成功 → 第 2 节视频依次播放。
2. 并发课节：多个页面同时运行，但每个页面都满足本节作业先于本节视频。
3. 作业最终失败：确认该节视频处理函数未被调用。
4. 演练模式：作业不提交但填答成功后进入视频。
5. `--phase video`：不处理作业，直接播放视频。
6. `--phase homework`：只处理作业，不播放视频。
7. 课节内多个视频：前一个未完成时不会点击后一个。
8. 一个课节的视频失败不会误标记整个课程其他课节。

### 回归与手工验证

- 保持原有 CLI、配置、备忘录、调度器和进度显示测试通过。
- 真实平台验证前只使用 `--phase video` 和小范围课节，确认任务点图标选择器、完成状态和多次弹题行为；未经用户许可不运行真实学习命令。

## 代码组织预期

- `src/study.mjs`：调整课节流水线为作业前置，再调用视频任务。
- `src/video-runner.mjs`：移除固定 `targetPercent` 终止逻辑，增加任务点状态轮询与每次弹题检测。
- `src/task-point.mjs`：支持 100% 默认播放、任务点完成等待和同步超时。
- `src/study-selectors.mjs`：集中任务点图标与状态选择器。
- `src/task-manifest.mjs`：为视频任务提供稳定任务点状态定位所需的身份信息。
- `src/study-progress.mjs`：显示媒体进度与任务点状态的区别。
- 对应测试覆盖解析器、播放器、弹题循环、课节流水线和 dry-run/phase 例外。

## 兼容性

- Node.js `>=20`。
- 不新增运行时依赖。
- 并发范围继续为 1–3，默认 1。
- 报告 schema 和备忘录 schema 保持现有版本。
- 既有 `--lesson`、`--course`、`--phase`、`--dry-run` 参数继续可用。
