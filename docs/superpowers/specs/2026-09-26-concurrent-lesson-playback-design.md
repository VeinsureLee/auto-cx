# 多课节并发学习与统一进度界面设计

## 背景

当前 `study` 命令已经支持通过 `--lesson` 选择单节、整章、范围或逗号列表，但所选课节仍在单一页面中逐节执行。终端只输出课节切换和最终报告，视频播放期间无法同时查看各课节的实时进度。

本次改造允许一个命令在多个页面中并发执行完整课节流程，并在同一终端统一显示每个页面的课节内容、执行阶段和视频进度。部分课程存在闯关依赖，因此并发调度必须服从平台目录中的锁定状态。

## 目标

1. 新增 `--concurrency N`，控制同一门课程同时运行的课节页面数。
2. 并发数默认为 1，允许范围为 1 到 3，保持现有串行行为兼容。
3. 每个工作页面独立执行完整的“视频 → 作业”流程。
4. 终端统一展示每个页面的课节、当前任务、阶段和视频进度条。
5. 只调度当前已解锁课节；课节完成后刷新目录并发现新解锁课节。
6. 并发更新学习备忘录时保持状态和文件写入一致。
7. 单个页面或课节失败不影响其他正在运行的页面。

## 非目标

- 不绕过平台的闯关锁定。
- 不 seek、拖动视频进度或伪造页面焦点。
- 不把并发上限扩展到 3 以上。
- 不同时并发处理多门课程；多门课程仍按课程顺序执行。
- 不改变现有视频目标百分比、作业答题和重试规则。
- 不引入第三方终端 UI 依赖。

## 命令行与配置

示例：

```powershell
npm run study -- --course 科研诚信 --lesson "1.1,1.2,1.3" --concurrency 3
```

规则：

- `--concurrency` 只能出现一次，参数必须是 1 到 3 的整数。
- 未提供时使用 `CHAOXING_STUDY_CONCURRENCY`；环境变量未配置时默认为 1。
- 命令行参数优先于环境变量。
- `--lesson 1` 继续表示选择整个第 1 章；`--lesson "1.1,1.2,1.3"` 表示显式列表。
- `--concurrency 1` 保持当前串行执行语义。

## 架构

采用单 Node.js 进程、单 Chromium 浏览器上下文和多页面工作池。

### 课程协调器

每门课程由一个协调器处理。协调器使用目录页面读取完整课节目录，刷新备忘录，并维护以下集合：

- `selected`：符合 `--lesson` 的课节；
- `active`：已分配给工作页面且尚未结束的课节；
- `attempted`：本轮已经完成或失败的课节，防止同一轮重复领取；
- `eligible`：未完成、未锁定、仍需执行且不在 `active`/`attempted` 中的课节。

协调器最多创建 `concurrency` 个工作页面。工作页面空闲时，从目录顺序最靠前的 `eligible` 课节中领取一个。某个工作页面结束后，协调器重新读取课程目录，再决定是补充普通待处理课节，还是启动刚刚解锁的后续课节。

若目录中只存在一个已解锁课节，即使指定 `--concurrency 3`，实际并发也自动降为 1。以“创新创业基础”为例，后续课节显示闯关锁定时不会被打开；前置课节完成且目录刷新为已解锁后，才进入调度队列。

当没有活动任务且目录中没有新的可执行课节时，该课程结束。仍锁定的课节保留 `locked` 状态并进入最终报告。

### 工作页面

每个工作页面只在同一时间拥有一个课节，并执行现有完整流程：

1. 打开课程目录；
2. 按 `knowledgeId` 定位并打开已分配课节；
3. 发现任务标签；
4. 自然播放所有视频到目标比例，并处理阻塞播放的视频弹题；
5. 处理该课节的章节作业；
6. 上报完成、失败或阻塞结果；
7. 返回空闲池或关闭。

工作页面之间不共享 Playwright `Page`，但共享浏览器上下文、登录状态、学习备忘录存储和终端进度控制器。

### 多门课程

多门课程继续按筛选结果顺序处理。并发限制只作用于当前课程，避免实际页面数变成“课程数 × 并发数”，也避免不同课程的进度和解锁刷新互相干扰。

## 终端进度界面

新增统一进度控制器，业务代码通过事件更新状态，不直接在动态区域中调用 `console.log`。

### 交互终端

当 `stdout.isTTY` 为真时，使用 ANSI 控制序列原地重绘固定区域，并限制刷新频率，避免每次媒体采样都造成闪烁。示例：

```text
创新创业基础  并发 2/3  已完成 1/6

页面 1  ▶ 1.2 创新创业课—远不止于……
        视频：任务点 1
        [██████████████░░░░░░] 68%  03:24/05:00  ×2

页面 2  ▶ 1.3 创业教育如何对应……
        作业：正在生成答案
        [████████████████████] 视频已完成

页面 3  ⏳ 等待可执行课节
```

每个页面状态包含：

- 工作页面编号；
- 课程名称和课节标题；
- 当前阶段：打开页面、发现任务、视频播放、视频弹题、读取作业、生成答案、提交、重试、完成、失败；
- 当前任务标题；
- 视频当前时间、总时长、播放倍速；
- 视频目标进度条。

视频进度条按 `currentTime / targetSeconds` 计算并限制在 0% 到 100%。因此配置目标为视频时长的 95% 时，达到 95% 即显示进度条 100%；时间文本仍展示实际媒体时间和总时长，避免把目标进度误认为完整视频百分比。

进入作业阶段后，视频条保留为“视频已完成”，同时更新作业阶段文本。总览显示活动页面数、并发上限、完成课节数和所选课节总数。

### 非交互终端

当输出被重定向或不支持 TTY 时，不发送 ANSI 控制序列。仅在以下节点写普通日志：

- 页面领取课节；
- 阶段变化；
- 视频进度跨越新的 10% 档位；
- 完成、失败或阻塞。

这样既保留可观察性，也避免每 1.5 秒产生一行日志。

### 日志协调

现有学习流程中的提示和警告改为通过进度控制器的 `log`/`warn` 接口输出。TTY 模式下，控制器先清除动态区域，输出持久日志，再重绘进度；非 TTY 模式直接输出。最终报告打印前停止动态刷新并恢复终端光标。

## 数据流

1. CLI 解析课程、课节、阶段、演练模式和并发数。
2. `runStudy` 创建浏览器上下文、进度控制器和学习备忘录存储。
3. 课程协调器读取目录并产生当前可执行课节。
4. 空闲工作页面领取课节并发运行。
5. `playManifestVideo` 通过现有 `onProgress` 回调把媒体采样发送给进度控制器。
6. 视频弹题、作业和重试逻辑发送阶段事件。
7. 每个状态变化通过串行化的 `StudyMemoStore.mutate` 更新备忘录。
8. 页面结束后，协调器刷新目录并继续调度。
9. 所有课程结束后停止进度界面，构建并写出既有 JSON/Markdown 报告。

## 状态与并发安全

当前 `StudyMemoStore.mutate` 可以被多个异步任务同时调用。改造后存储内部维护 Promise 队列，每次 mutation 按调用顺序执行“修改内存状态 → 原子写 JSON → 原子写 Markdown”。一次 mutation 失败不会永久阻塞后续队列，但错误会返回给对应调用者。

目录刷新和课节状态更新都使用同一队列。调度器只根据已完成的目录刷新结果分配任务，避免读取写入中的中间状态。

实时媒体进度只保存在进度控制器内存中，不提高备忘录落盘频率。原有 `done`、`failed`、`blocked`、`submitted` 等持久状态保持不变，不升级备忘录 schema。

## 错误处理

- 单个课节失败：写入原有失败状态，页面显示失败，释放槽位，其他页面继续。
- 页面意外关闭：将该课节标为失败，不把它在同一轮立即重复调度。
- 视频停滞或弹题无法处理：沿用现有 blocked/failed 判定。
- 目录刷新失败：当前课程停止调度新任务；已运行页面允许收尾，随后把错误附加到最终报告。
- 浏览器或上下文失效：视为全局致命错误，停止所有页面并生成失败现场报告。
- Ctrl+C 或异常退出：停止进度刷新、恢复光标并关闭浏览器；已经落盘的课节状态保留。

## 代码组织

预计涉及：

- `src/study-cli.mjs`：解析和验证 `--concurrency`，初始化最终输出。
- `src/config.mjs`：增加 `CHAOXING_STUDY_CONCURRENCY`，默认 1、最大 3。
- `src/study.mjs`：把串行课程循环改造成锁定感知的页面工作池，并发送阶段事件。
- `src/study-progress.mjs`：新增统一进度状态、进度条格式化、TTY 重绘和非 TTY 里程碑日志。
- `src/study-memo.mjs`：串行化并发 mutation。
- `src/video-runner.mjs`：把媒体采样和视频弹题阶段转发给进度控制器。
- `README.md`、`.env.example`：记录命令示例、默认值和课程锁定语义。
- 对应测试文件：覆盖 CLI、配置、调度、状态存储和进度渲染。

## 测试策略

### 单元测试

- CLI：缺值、重复、非整数、低于 1、高于 3以及合法值。
- 配置：默认并发 1、自定义 1 到 3、非法环境变量。
- 调度：并发数不超限；锁定课节不领取；已活动/已尝试课节不重复；刷新后新解锁课节可领取。
- 备忘录：多个并发 mutation 最终全部保留，并且写入顺序稳定。
- 进度：百分比钳制、固定宽度进度条、时间格式、阶段文本、TTY 和非 TTY 输出策略。

### 回归测试

- `--concurrency 1` 的执行次序与现有行为一致。
- `--phase video`、`--phase homework` 和 `--dry-run` 在并发工作页面中保持原语义。
- `--lesson` 单节、整章、范围和列表筛选保持兼容。
- 最终 JSON/Markdown 报告格式保持兼容。

### 手工验证

1. 在非闯关课程选择三个已解锁课节，以 `--concurrency 3 --phase video` 验证三个页面同时自然播放并显示独立进度条。
2. 在“创新创业基础”使用 `--lesson 1 --concurrency 3`，确认被锁定课节不会提前打开，实际并发自动降为 1，并在目录解锁后继续下一节。
3. 运行完整模式，确认不同页面可分别处于视频、作业和完成阶段。
4. 使用 `--concurrency 1` 回归串行流程。
5. 把输出重定向到文件，确认没有 ANSI 控制字符且日志按 10% 里程碑输出。

## 兼容性与交付标准

- Node.js 版本要求保持 `>=20`。
- 不新增运行时依赖。
- 既有命令不传 `--concurrency` 时保持串行。
- 全部自动化测试和语法检查通过。
- 三页面进度显示稳定，不出现日志覆盖、重复调度或备忘录丢失更新。
- 闯关课程不会打开目录标记为锁定的课节。
